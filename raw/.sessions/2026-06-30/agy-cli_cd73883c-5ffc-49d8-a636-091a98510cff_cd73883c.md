### Plugins (`/plugins`)
Plugins act as "toolboxes" that bundle related skills or external integrations. They extend an agent's capabilities modularly but rely on the agent for decision-making. Keeping them separate allows for easy swapping or upgrading of integrations without touching core agent logic.

### Workspaces, Reports, and Artifacts (`/workspace`)
Following **MetaGPT's Standardized Operating Procedure (SOP)**, it is highly recommended to have a dedicated, automatically generated `workspace` directory. 
*   **Shared Memory Pool**: The workspace acts as a shared drive where agents (e.g., Product Manager $\rightarrow$ Architect $\rightarrow$ Engineer) can read and build upon artifacts created by previous steps.
*   **Organization by Type**: Separate outputs into documentation (PRDs, System Designs), source code, tests, and reports.
*   **Persistence**: Ensure this directory persists across runs or container restarts to maintain context and allow for incremental development.

### Scripts (`/scripts`)
Keep standalone scripts out of the core application logic. Use this directory for utility tasks such as database seeding, running batch evaluations, or deployment scripts.

## 4. Key Considerations for Scalability
*   **Use Subgraphs for Complexity**: As your application grows, avoid creating one massive "god graph." Break down complex workflows into subgraphs that are independently testable and reusable.
*   **Observability & Governance**: Implement tracing, logging, and metrics early on. You need to understand why an agent took an action and whether it succeeded. Include access controls and security guardrails in your orchestration layer.
*   **Start Small**: Build a robust single-agent system with well-defined tools before graduating to multi-agent parallel architectures. Do not spawn excessive agents for simple tasks, as the coordination overhead will quickly outweigh the benefits.
